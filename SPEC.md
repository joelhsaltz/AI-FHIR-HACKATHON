# SPEC.md — Requirements, Scope, and Design Decisions

## Overview

A three-session educational hackathon for BMI 512 (Clinical Informatics and AI)
at Stony Brook University. Students learn FHIR data querying and AI agent
patterns through hands-on Jupyter notebooks.

## Audience

Mixed-background graduate students: MDs with varying CS experience, PhD and MS
students from computer science and biology. No prior FHIR or AI agent experience
assumed.

## Session Requirements

### Session 1: FHIR Fundamentals

- **Goal:** Students manually query a public FHIR server using Python code
  generated by Claude (web UI).
- **Deliverable:** None (learning session).
- **Requirements:**
  - No API key needed — only `requests` against the public FHIR server.
  - Students use Claude web UI to generate Python code, paste into Colab, run it.
  - Three-step clinical pipeline: search Conditions, follow references to
    Patients, search Observations for HbA1c values.
  - Backup notebook (`session1_backup.ipynb`) provides a local Flask FHIR server
    with embedded Synthea data for when the SMART server is down.

### Session 2: AI Agent Basics

- **Goal:** Students observe an AI agent autonomously executing the same pipeline
  from Session 1 using tool use (function calling).
- **Deliverable:** None (observation session).
- **Requirements:**
  - Anthropic API key required (stored in Colab Secrets).
  - 3 tools: `search_conditions`, `get_patient`, `search_observations`.
  - Hardcoded clinical question — students predict the tool call sequence, then
    compare to actual agent behavior.
  - Tool call trace printed for analysis.

### Session 3: Open-Ended Agent Exploration

- **Goal:** Students design custom clinical questions, run them through a 6-tool
  agent, find and document failures.
- **Deliverable:** JSON file (`hackathon_session3_*.json`) containing questions,
  tool call logs, agent answers, and a timestamp.
- **Requirements:**
  - 6 tools: original 3 + `search_medications`, `search_encounters`,
    `search_all_conditions`.
  - Students run 2+ questions, document at least 1 failure/surprise.
  - Final reflection on trustworthiness and MCP.

## Clinical Scenario

**Primary question:** "Find patients with Type 2 diabetes, retrieve their most
recent HbA1c values, and identify those with poor glycemic control (HbA1c >
7.0%)."

**Coding systems:**
- Conditions use SNOMED CT (not ICD-10): Type 2 Diabetes = `44054006`,
  Hypertension = `59621000`.
- Lab values use LOINC: HbA1c = `4548-4`, Blood Pressure = `85354-9`,
  Creatinine = `2160-0`.

**HbA1c threshold:** >7.0% for poor control. This is lower than some clinical
guidelines because Synthea-generated data skews toward lower values.

## Design Decisions

### Anthropic-only architecture

Originally planned as dual-provider (Anthropic + Azure OpenAI). Simplified to
Anthropic-only to reduce cognitive load for students. See
`docs/SIMPLIFICATION_SUMMARY.md` for details.

### No verification hash in deliverable

The Session 3 deliverable originally included a SHA-256 hash of tool call data.
Removed because it was unnecessary for an informal hackathon and would confuse
students. The JSON report contains questions, tool call logs, answers, and a
timestamp — sufficient for grading.

### Annotated notebooks generated by script

Instructor annotations are inserted by `create_annotated_notebooks.py` rather
than hand-edited into notebooks. This keeps source notebooks clean and ensures
annotations stay synchronized with the originals.

### Content block serialization

The Anthropic Python SDK's Pydantic content blocks cause serialization errors
when appended directly to the messages list. All notebooks manually serialize
content blocks to plain dicts. This is documented in the agent loop code.

## Scope

### In scope
- Three student notebooks (Colab-ready)
- Three instructor notebooks + annotated variants
- Orientation PDFs for each session
- FHIR server validation script
- Notebook test scripts
- Annotated notebook generation script

### Out of scope (potential future work)
- Batch grading script (`grade_session3.py`)
- MCP server wrapping the FHIR tools (potential Session 4)
- Multi-provider support
- Additional clinical scenarios beyond diabetes/HbA1c

## Known Limitations

- Hypertension SNOMED code (59621000) returns 0 results on the SMART FHIR server.
- Creatinine observations (LOINC 2160-0) are sparse or absent in the dataset.
- SMART FHIR server occasionally returns 500/502 errors — backup notebook
  provides fallback for Session 1.
