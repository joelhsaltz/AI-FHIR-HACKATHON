# FHIR Clinical Education Notebook Framework: AI-Assisted Generation of Interactive Clinical Informatics Exercises

Teaching AI agent concepts to clinical informatics trainees presents a fundamental challenge: students who reason fluently about diagnoses, lab values, and medications are often novice programmers who cannot engage with agent code directly. We developed a framework for generating self-contained Google Colab notebooks that teach AI agent patterns through FHIR data queries, requiring no programming from students. The framework uses a scenario-driven architecture in which clinical scenarios are designed as structured documents specifying a clinical question, required evidence types mapped to FHIR resources, classification categories with genuine ambiguity, and minimum query requirements that prevent single-query shortcuts. Generator scripts produce notebooks where all code is hidden behind Colab form cells, and students interact entirely through dropdown menus. Four domain-independent AI agents — a Clinical Scenario Designer, Synthetic Data Architect, Clinical Education Reviewer, and Notebook Implementation Reviewer — collaborate through shared scenario documents and a structured communication protocol to design scenarios, generate synthetic patient data, evaluate pedagogy, and verify technical correctness. Verification uses a Vertex AI Workbench pipeline that programmatically executes notebooks against a live FHIR R4 server via SSH tunnel and Jupyter MCP, replacing fragile browser automation.

The first use case, deployed in BMI 512 (Clinical Informatics and AI) at Stony Brook University, teaches diabetes management complexity assessment using 1,027 synthetic patients across six phenotypes loaded into a FHIR R4 server. Students act as the clinical decision-making agent — choosing which FHIR queries to run (HbA1c, eGFR, UACR, medications, conditions), interpreting results, and classifying patients as Routine, Moderate complexity, High complexity, or No diabetes — then write natural-language prompts directing a Claude AI agent to perform the same task autonomously. The scenario is calibrated so that no single data point resolves classification: students who check only eGFR miss early kidney damage detectable via UACR, and students who skip the problem list miss non-diabetic controls. This design forces the iterative evidence-gathering loop (observe, decide, act, update, repeat) that defines agent behavior. The framework is FHIR-specific but pedagogy-agnostic — planned use cases include adverse event evaluation, information extraction from radiology and pathology reports, and population health queries — and is designed so that other instructors can fork the repository, connect their own FHIR server, and generate notebooks for new clinical domains.
